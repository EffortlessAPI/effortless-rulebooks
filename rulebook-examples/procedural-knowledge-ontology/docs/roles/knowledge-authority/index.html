q2-authority-elicitation-method-monoculture

Loop 1 reports IsOverdueForReview=6/7, and I do not trust the number. It is computed from AgeDays, which is DATETIME_DIFF from ValidFrom — the date the claim became true, not the date anybody last looked at it. A fragment reviewed and reaffirmed last week reads exactly as overdue as one nobody has opened since it was written. I need the date of the last actual review recorded as a fact.

This is structural debt, and it is the kind that produces a plausible-looking wrong answer rather than an error. ValidFrom is a bitemporal validity bound; LastReviewedAt is a stewardship event. Deriving the second from the first is a category error that makes 6/7 unfalsifiable — there is no data that could make it read 5/7. The honest fix is a raw LastReviewedAt column, with the old inference retained as an explicit fallback-free comparison so the discrepancy itself becomes visible.
